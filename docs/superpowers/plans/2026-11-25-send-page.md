# Send page (Step 17) Implementation Plan

**Working agreement (mandatory):** keep this plan in sync with reality. Append every divergence to the Drift Log. When a drift changes a decision of the spec, add a new spec doc rather than rewriting the spec.

**Goal:** the library only keeps; a new « Envoyer » page sends one photo (camera, device, library) to several friends in one action and lists my sends, newest first; the Cloudinary image survives while a photo or a send uses it.

**Architecture:** server: a `Send` model, the two share routes take `friendIds` and answer per-friend outcomes plus the recorded send, a `sends` feature lists and deletes history lines, `lib/image-uses.ts` counts photos and sends before destroying an image. Client: `/send` page with `useSendHistory`, a source panel and a library picker in front of the existing `ShareSheet`, tab bar and top bar updated, the add panel reduced to its two source tiles.

**Tech Stack:** Node 24, TypeScript, Express 5, Prisma 6.19 (MongoDB), Vitest; React 19, React Router, Radix/shadcn, sonner, Tailwind 4, Biome 2.

## Global Constraints

- No new dependency. No Docker, never port 3000, never read `.env`, never `db:seed`. `pnpm db:push` and the Bruno run are handed to the controller (the `Send` collection needs its indexes).
- No `as` casts, explicit return types on exported functions, literal unions. Functions ≤ 30 lines, files ≤ 300, ≤ 5 params. Comments say why. Server logs through `lib/logger.ts`, identifiers only.
- Same-commit rules: endpoint → Bruno; service rule → colocated `*.test.ts`; visible behaviour → `docs/produit/` (French, no technical terms, new rule numbers after R-PAR-57, R-BIB-65, R-APP-66); flow or API change → `ARCHITECTURE.md`.
- Gates per commit: `pnpm exec biome check client server/src server/prisma server/bruno docs` and `pnpm typecheck`; at each branch tip `pnpm test`; at the stack tip `pnpm build`.
- Keep `LibraryPage.tsx` and `LibraryHeader.tsx` untouched (parallel `feat/library-timeline`).
- Never touch the author's Docker files (`server/Dockerfile`, `server/.dockerignore`, `compose.yaml`, `NOTE.md`, `.vscode/settings.json`).

## Interfaces

- Server types (`server/src/types.ts`, copied in `client/src`): `SendRecipient = { id; displayName }`, `SentPhoto = { id; url; thumbnailUrl; createdAt; message: string | null; recipients: SendRecipient[] }`, `SendPage = { sends: SentPhoto[]; nextCursor: string | null }`, `SendOutcomeStatus = 'sent' | 'duplicate' | 'not_friends'`, `SendOutcome = { friendId; status }`, `SendResult = { send: SentPhoto | null; outcomes: SendOutcome[] }`. New error code `SEND_NOT_FOUND` (404).
- `lib/image-uses.ts`: `countImageUses(prisma, cloudinaryId): Promise<number>`, `destroyUnusedImage(deps: ImageUseDeps, cloudinaryId): Promise<boolean>`.
- `features/sends/sends.repository.ts`: `NewSend`, `SendRecord`, `SendsRepository = { create, findPage, deleteOwned, countImageUses }`.
- `features/photos/photos.share.ts`: `shareFromLibrary(deps, { senderId, photoId, friendIds, message })`, `shareFromDevice(deps, { senderId, file, friendIds, message })` → `ShareResult = { send: SendRecord | null; copies: PhotoRecord[]; outcomes: SendOutcome[] }`.
- Client: `photosApi.postLibraryShare(photoId, friendIds, message)`, `postDeviceShare(file, friendIds, message)` → `ShareResult` (`'done'` with outcomes, `'failed'`, `'unauthenticated'`); `sendsApi.fetchSendPage`, `deleteSend`; `useSendHistory()`.
