# J1 MVP: photo upload and live frame

- Date: 2026-11-23
- Branch: `feat/j1-mvp` from `develop`, one PR squash-merged into `develop`
- Goal (brief J1): working locally, no Docker. A relative enters a nickname, takes or picks a photo on a phone, and it shows up on the frame page without a reload.
- Non-goals: Docker (J2–J4), visual polish, slideshow, Cloudinary thumbnails, pagination (J5), auth, rate limiting.
- AI usage: plan drafted by a Claude Code planning subagent from the repo and the brief, then adjusted with the author's decisions below.

## Data: Prisma model

```prisma
model Photo {
  id        String   @id @default(auto()) @map("_id") @db.ObjectId
  url       String
  publicId  String   @unique
  nickname  String
  createdAt DateTime @default(now())

  @@index([createdAt])
}
```

Pushed with `pnpm db:push` (no migrations with MongoDB).

## Environment variables

No new names. `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` become required in `config.ts`: the server fails at startup if one is missing, like `DATABASE_URL`. The client has no env vars and only calls relative paths through the Vite proxy.

## API

Errors: `{ "error": ApiErrorCode }` with

```ts
type ApiErrorCode =
  | 'NICKNAME_INVALID'
  | 'PHOTO_MISSING'
  | 'UPLOAD_INVALID'
  | 'PHOTO_TOO_LARGE'
  | 'FORMAT_UNSUPPORTED'
  | 'IMAGE_UNREADABLE'
  | 'SERVER_ERROR'
```

### `POST /api/photos`

- `multipart/form-data`: fields `nickname` (text) and `photo` (one file).
- Multer: `memoryStorage`, `limits: { fileSize: 10 * 1024 * 1024, files: 1 }`, `upload.single('photo')`.
- Pipeline: nickname check → file present → mimetype allowlist → Sharp → Cloudinary → Prisma create → `io.emit('photo:new', dto)` → `201` with the `Photo` DTO.
- Sharp: `rotate()` (EXIF orientation, phone photos) → `resize({ width: 1920, height: 1920, fit: 'inside', withoutEnlargement: true })` → `flatten({ background: '#ffffff' })` (PNG transparency) → `jpeg({ quality: 85 })`. Metadata, GPS included, is dropped by default. The client-declared mimetype cannot be trusted: Sharp decoding the image is the real validation.
- Cloudinary: upload the JPEG buffer as a data URI into folder `familyframe`, keep `secure_url` and `public_id`. Simpler to explain than wrapping `upload_stream` in a Promise; the base64 overhead is fine at 10 MB or less.

| Case                                                 | Status | `error`                            |
| ---------------------------------------------------- | ------ | ---------------------------------- |
| Nickname missing, blank after trim, or over 30 chars | 400    | `NICKNAME_INVALID`                 |
| No file                                              | 400    | `PHOTO_MISSING`                    |
| Other `MulterError` (wrong field, several files)     | 400    | `UPLOAD_INVALID`                   |
| `MulterError` `LIMIT_FILE_SIZE`                      | 413    | `PHOTO_TOO_LARGE`                  |
| Mimetype not JPEG/PNG/WebP                           | 415    | `FORMAT_UNSUPPORTED`               |
| Sharp throws (corrupt or fake image)                 | 422    | `IMAGE_UNREADABLE`                 |
| Anything else (Cloudinary, DB)                       | 500    | `SERVER_ERROR` (real error logged) |

Express 5 forwards async rejections to the error middleware. One 4-argument error handler in `index.ts` handles `MulterError` and the 500 fallback; 400/415/422 are answered inline in the route.

### `GET /api/photos`

`200 Photo[]`, newest first, `take: 20` (fixed constant, pagination in J5).

### DTO (REST and Socket.IO)

```ts
type Photo = { id: string; url: string; nickname: string; createdAt: string } // ISO 8601
```

`publicId` is not exposed. The server maps rows with `toPhotoDto()`.

### `GET /api/health`

Unchanged, reused as the Docker healthcheck in J2.

## Socket.IO

- Server → client: `photo:new` with a `Photo`, broadcast with `io.emit`. Client → server: none.
- `type ServerToClientEvents = { 'photo:new': (photo: Photo) => void }`, used as the generic on the server `Server` and the client `Socket`: typed payloads without casts.
- The route receives `io` explicitly: `createPhotosRouter(io)`.

## Client

`App.tsx`: `BrowserRouter` with `/` → `UploadPage`, `/frame` → `FramePage`. The current health-check `App.tsx` (and its `as` cast) goes away.

### Upload page (`/`)

- Nickname `<input required maxLength={30}>`, initialised from and saved to `localStorage` (wrapped in try/catch: storage can be unavailable).
- Two file inputs: "Prendre une photo" (`accept="image/*" capture="environment"`) and "Choisir une image" (`accept="image/*"`). `capture` opens the camera directly and hides the gallery on mobile, and the brief asks for both.
- Preview with `URL.createObjectURL`, revoked on change and unmount.
- Submit with `FormData` to `POST /api/photos`. `status: 'idle' | 'sending' | 'success' | 'error'`, button disabled while sending.
- Error body read as `unknown`, narrowed to `{ error: ApiErrorCode }` with a guard, mapped to French text by a `Record<ApiErrorCode, string>`; unknown shape or network failure → generic message.
- On success: reset the file, keep the nickname.

### Frame page (`/frame`)

- `useEffect`: `const socket: Socket<ServerToClientEvents> = io()` (same origin, through the Vite proxy).
  - `socket.on('connect', loadPhotos)`: first load and refetch after a reconnect, so photos sent during an outage are not missed.
  - `socket.on('photo:new', …)` prepends, skipping ids already present (fetch/event race).
  - Cleanup: `socket.disconnect()` (safe under StrictMode double mount).
- `loadPhotos` reads `GET /api/photos` as `unknown`, checked with `Array.isArray(data) && data.every(isPhoto)`.
- Layout: `photos[0]` large (`object-fit: contain`, about 70vh) with nickname and date (`toLocaleString('fr-FR')`); the rest as wrapping thumbnails with nicknames; empty state "En attente de la première photo…".
- `index.css`: drop the global `body` centering that would break this layout.

## Known limitations (accepted for J1)

- If the DB write fails after the Cloudinary upload, the asset is orphaned (logged with its `publicId`, no cleanup).
- No auth or rate limiting: anyone on the LAN can post.
- HEIC (iPhone) is not decodable by prebuilt sharp. Not tested in J1 (test device is Android); Safari usually converts to JPEG for `accept="image/*"`.
- J2: sharp ships platform-specific binaries, so it must be installed inside the image, never copied from the Windows `node_modules`. The production server needs an SPA fallback so `/frame` serves `index.html`.
